# TavernAgent v2

`crates/tavernagent_v2` 是独立的 Rust **PPO-Clip + GAE** 训练项目。模型结构、观测和紧凑动作接口参考 v1；训练改为八座位同步 on-policy 自博弈。

截至 2026-11-13，正式结构固定为 **C（entity-actions）：320×6、embedding=32、共享实体编码器与对象条件动作头，共 3,473,102 个参数**。A/B 结构及旧 CUDA 网络实现已移除；只支持 CPU FP32。Checkpoint 必须明确记录 `architecture=entity-actions`，不加载 A/B 或缺少结构标识的旧模型。新增商店生命值支付特征后输入 schema 已改变；此前 C checkpoint 需使用对应旧版二进制恢复，当前代码不自动迁移。正在运行的实验保持旧版输入和二进制。

训练 baseline 为 **Freeze-and-End、λ=0.96、terminal-value-coef=0.1、entropy=0.03、epochs=1、games=64、batch=1024**。新训练默认使用学习率余弦调度：第 1～5000 轮保持 **1e-4**，5000～10000 轮余弦下降至 **2e-5**，10000 轮之后保持 **2e-5**。CLI 的结构/宽度默认值为 C/320；λ、终局辅助损失与 Freeze-and-End 仍需显式使用以下配方。

结构实验归档时已停止其训练、评估、同步和通知任务，并保留 C 两种子各 1000、2000、……、10000 轮的完整训练 checkpoint（共 20 个，包含 9000 轮异常模型），权重不随 Git 发布；[保留清单](../models/tavernagent_v2/manifest.json)记录种子、轮数、配置、优化器计数及 SHA-256。其余实验权重、日志、诊断脚本、回放和临时图表已清理。下文内联结果与统计口径是实验记录，历史产物名称仅用于标识来源，不是运行依赖。

## 快速使用

以下命令从仓库根目录执行，先构建并训练，再对生成的 checkpoint 续训或评估。`runs/` 下的路径均为示例输出，不是仓库附带文件。`--iterations` 表示累计训练轮数，每轮采集 `--games` 个完整八人游戏。

```bash
cargo build --release -p tavernagent_v2

# 下一轮实验 baseline：从头训练；使用新的训练种子
target/release/tavernagent_v2 train \
  --hidden 320 --blocks 6 --embedding-dim 32 \
  --lr 1e-4 --gae-lambda 0.96 --entropy-coef 0.03 \
  --freeze-at-end --terminal-value-coef 0.1 --value-coef 0.5 \
  --games 64 --epochs 1 --batch 1024 --workers 16 \
  --iterations 3000 --seed 1100000000 --save-every 500 \
  --out runs/tavernagent_v2/model.npz

# 继承保存的超参数、优化器和 RNG，继续到累计 5000 轮
target/release/tavernagent_v2 resume \
  --checkpoint runs/tavernagent_v2/model.npz \
  --iterations 5000 --workers 16 --save-every 500

# 两种固定对手分别评估；默认 greedy，加入 --sample 改为概率采样
target/release/tavernagent_v2 eval \
  --model runs/tavernagent_v2/model.npz --opponent scripted \
  --games 1024 --workers 16 --seed 10000000 --out runs/tavernagent_v2/scripted.json
target/release/tavernagent_v2 eval \
  --model runs/tavernagent_v2/model.npz --opponent teacher \
  --games 1024 --workers 16 --seed 10000000 --out runs/tavernagent_v2/teacher.json
```

`train --iterations 0` 只保存初始化模型、零 Adam 状态和初始 RNG，可用于未训练基线并继续训练。完整选项见各子命令的 `--help`。

| 参数 | CLI 默认值 |
| --- | ---: |
| games | 64 |
| batch | 1024 |
| workers | 16 |
| lr（初始值） | 1e-4 |
| lr-schedule | cosine |
| lr-min | 2e-5 |
| lr-decay-start / lr-decay-end | 5000 / 10000 |
| gae-lambda | 0.95 |
| entropy-coef | 0.03 |
| epochs | 1 |
| gamma | 1 |
| clip-range | 0.2 |
| target-kl | 0.02 |
| value-coef | 0.5 |
| max-grad-norm | 0.5 |
| weight-decay | 0.01 |

下一轮 baseline 在上表基础上将 `gae-lambda` 改为 **0.96**，开启 `freeze-at-end`，将 `terminal-value-coef` 设为 **0.1**。不启用连续 Freeze 屏蔽、回合感知 λ、名次分布 critic、血量输出头或 target clipping，模型为 3,473,102 个参数。`workers=16` 是运行起点，可按实际吞吐调整。

学习率按累计训练轮数 `t` 计算，而非 minibatch 数或本次续训长度：衰减区间内 `lr(t) = lr_min + (lr - lr_min) × (1 + cos(π × (t - start)/(end - start))) / 2`，例如第 7500 轮为 6e-5。每轮所有 minibatch 使用同一个学习率；日志与 checkpoint 内的 history 记录 `learning_rate`。调度配置随 checkpoint 保存，续训不会重新开始衰减。`--lr-schedule constant` 可禁用调度；`--lr` 在 cosine 模式下表示初始值。

缺少调度字段的历史 checkpoint 按 **constant** 恢复，保持原实验行为。通过 `fork --lr-schedule cosine --lr 1e-4 --lr-min 2e-5 --lr-decay-start 5000 --lr-decay-end 10000` 可显式切换；其他状态保持不变。`fork --lr` 单独使用时继承原调度模式，恒定学习率对照应明确指定 `--lr-schedule constant`。

本次默认调度是基于后期降学习率实验选定的下一轮配方，尚未完整实测这条余弦曲线。8000→10000 轮阶跃降学习率的双种子实验中，同池最终平均 Elo：恒定 1e-4 为 1146.6、5e-5 为 1168.6、2e-5 为 1172.7；后两者的差异不足以认定强度优劣。每个候选累计 4000 轮中 KL 提前停止分别为 28 和 2 次，因此暂选 2e-5 作为后期下限。该 arena 排除了 seed1100000000 的历史 9000 轮异常模型，但包含两个种子的 10000 轮对照。

`games` 为训练每轮完整游戏数；`train`、`resume`、`eval` 均默认 16 workers。恢复已有 checkpoint 使用其保存的训练超参数，不从新的命令行缺省值重建。

历史 A 比较使用五个训练种子，C 使用两个训练种子；详细预算、评估口径与限制见实验结果。从头训练无需历史权重，续训使用自己生成或保留清单中对应的完整 checkpoint。

短流程检查可以使用小模型和短回合预算；它不衡量策略强度：

```bash
target/release/tavernagent_v2 train \
  --iterations 2 --games 2 --workers 2 --hidden 16 --blocks 1 --embedding-dim 2 \
  --max-turns 3 --action-cap 8 --epochs 1 --batch 64 \
  --out runs/tavernagent_v2-smoke/model.npz
```

## CUDA 后端

C 的 CUDA forward/backward/Adam 暂未实现。`--backend cuda` 与启用 `cuda` feature 后的 `cuda-check` 均明确报错，不会静默回退到 CPU。旧 A 的 CUDA 网络、FFI、核文件和验证实现已删除，`cuda` feature 仅保留未来实现的入口；当前构建和运行不需要 CUDA 依赖。下文 GPU 数据仅描述历史实验。

## 模型与游戏接口

默认模型为 **3,473,102 个参数**，hidden=320、6 个 pre-norm 残差块、共享卡牌 embedding=32。

```text
1718 个保留浮点特征 + 22 位回合/星级 one-hot + 57 个卡牌 embedding
  → 共享实体编码器（64 维）与全局编码器（128 维）+ 116 位动作 mask
  → 3892 维 → Linear(3892, 320) → LayerNorm → GELU
  → 6 个 pre-norm 残差块，FFN 320 → 480 → 320
  → 全局动作头 + Buy/Sell/Activate/Choose/Play 对象条件动作头 → 116 logits
  → value：Linear(320, 128) → GELU → Linear(128, 1) → tanh
```

宽度、深度、embedding、激活函数、残差缩放和 head normalization 仍可配置。没有结构切换参数，没有 BF16 推理实现。

### 实体编码与对象动作头

C 将相同类别的卡牌槽交给共享的两层 MLP（隐藏层、输出均为 64）：英雄/技能/任务/饰品等元信息、场上随从、手牌、商店、发现选项、对手公开摘要分别共享一个编码器。输入为现有 32 维卡牌 embedding 与该实体的原始属性；不引入额外游戏信息。57 个输出保持固定槽位顺序，缺席实体的输出屏蔽为零，避免丢失站位。剩余数值特征及回合/星级 one-hot 经独立 MLP 编码为 128 维，再与实体表示、116 位合法动作 mask 拼成 3892 维主干输入。主干仍为 pre-norm 残差 MLP，policy/value 接口不变。

动作头使用全局主干输出和实体编码；Buy、Sell、Activate、Choose 分别以全局主干输出和对应实体表示打分，同类动作的各槽位共享 64 维隐藏层。Play 使用全局输出、手牌、目标位置的场上实体表示及 7 位位置 one-hot；空位置保留位置编码。End、Refresh、Freeze、Upgrade、技能等动作仍由全局线性头输出。全部结果按原动作编号组成 116 个 logits，统一 masked softmax，不做分层动作采样。

C 的动作头按输入分块计算同一层线性变换：每个动作类别只投影一次全局特征；Play 分别投影 10 个手牌槽和 7 个场上槽，再组合成 70 个动作，并直接读取位置 one-hot 对应的权重行。反向传播先汇总共享投影的梯度，再计算输入和权重梯度；不再为每个动作复制整份全局输入。权重分块直接借用原矩阵，不复制权重。网络、参数布局、116 个 logits、合法动作规则及 PPO 配方均不变，旧 C checkpoint 可直接续训；浮点求和顺序变化，因此不保证逐位一致。测试保留展开计算的参考实现，对比单样本和批量的 logits、masked softmax、全部动作头参数及主干/实体输入梯度，并保留全网有限差分检查。

计算优化的短程验证：从同一 C-1500 checkpoint 分别续训 5 轮，64 局/轮、16 workers，旧实现平均 9.205 秒/轮，新实现 8.094 秒/轮，吞吐提高约 13.7%；梯度计算从 4.914 降至 3.930 秒/轮。五轮各自的决策数量均相同，结束后的模型浮点数组最大绝对差为 `3.64e-6` 以内，权重和 Adam 状态均有限。正式两种子分别从 1963、1993 轮保留完整 checkpoint 续训，随后随 A/B 一起将累计目标延长至 10000 轮；64 workers 下，切换前各 20 轮与切换后各 14 轮的均值从约 5.01～5.05 降至 4.33～4.35 秒/轮，吞吐提高约 16%。后者是切换前后短窗口，不能视为严格配对测速或强度提升证据。该轮 bot/arena 评估继续使用切换前的固定评估二进制，保持评分执行口径一致。

对象动作头的参数预算、B/C 同配方对照、共享联赛与吞吐数据见第三轮实验结果。测试保留独立的展开计算参考作为数值校验，不保留 A/B 执行路径。

### 观测

原始观测为 **3244 个浮点数、124 个卡牌索引、116 位动作 mask**。浮点数包含引擎的 3235 个特征及额外的伤害上限保护位：存活且当前存在战斗伤害上限、生命值加护甲严格大于上限时为 1；使用招募阶段开始时的存活人数判断伤害上限资格。另外追加 8 位 `costs_health`，每个商店槽对应一位：通过当前 `slot_price()` 获取是否支付生命值，生命值购买为 1，金币购买、免费购买或空槽为 0。现有 cost 仍表示实际支付数量（除以 5），免费购买为 0。新增特征进入对应商店实体的共享编码器及购买动作头，随每次观测重新计算，不改引擎/v1 的输入布局。共享商店编码器增加 64 个参数；旧版 3236 浮点输入的 checkpoint 会被 schema 校验拒绝，历史实验结果仍对应旧版 3,473,038 参数。

网络在 v1 的特征筛选基础上新增商店支付特征，保留 1718 个数值特征、57 个卡牌槽，再加入回合与星级 one-hot 和动作 mask。回合 one-hot 共 16 位，T16 及以后共用最后一位；星级共 6 位，6/7 本共用最后一位。原回合、星级标量仍保留。

`observe_seat` 按获得来源映射饰品：普通饰品进入普通槽；英雄技能、任务奖励来源映射到对应槽；Orb 壳本身不占槽，其产生的饰品按来源表示。该映射只改变输入表示，不修改引擎效果，待处理的发现选项也保持原样。

已获得奖励槽只显示 `player.rewards` 的最后一项：虚灵证物选完后显示当前选中的奖励，下一次选择后同步替换。如果最后一个奖励提供了饰品，该槽显示对应饰品 ID；其他奖励的饰品不会挤占普通饰品槽。任务奖励只映射到奖励槽，大帝的技能槽保留原技能 ID。仍保留第一个进行中任务及其目标奖励的独立槽位，发现候选项不受映射影响。这些修改不增加输入维度，默认每个槽仍为 32 维 embedding，但与历史 checkpoint 训练时的奖励编码语义不同；历史实验结果使用修改前的编码。

### 动作与训练约束

- **去掉 Move**。0–45 与引擎动作索引一致；46–115 为 `46 + hand * 7 + position`。
- **Play / Magnetize 合并**。在当前状态下，目标为兼容的已占用位置时执行 Magnetize，否则执行普通 Play；法术使用位置 0。合法性检查与执行使用相同映射，引擎原动作 API 不变。
- **金币 ≥ 3 时屏蔽 EndTurn；通常屏蔽 Cancel**。若移除某动作会使合法集合为空，则保留逃生动作。
- 默认每座位每回合总动作上限 100、Freeze 按键上限 5；预算配置仍保留 Move 上限 10，但模型动作空间不提供 Move。
- 可选 `--block-consecutive-freeze`：同一座位在同一回合上次成功动作是 Freeze 时，下一次屏蔽 Freeze；其他成功动作或新回合恢复。其他座位行动不解除限制。该开关默认关闭，作为对照变量写入 checkpoint，训练、固定 bot 评估、混桌和开局采集统一读取。mask 仍保留 EndTurn/Cancel 的唯一动作逃生规则。
- 选英雄使用独立、带种子的均匀策略，不由网络决定，也不产生 PPO 样本。

训练与评估中的模型使用同一 mask。固定 bot 使用引擎动作和自身规则，不套用模型的训练约束。

## 训练与恢复

### 采样与 GAE

每轮固定当前参数，并行采集完整的八座位自博弈游戏，然后执行 PPO 更新。所有实际招募决策按温度 1 的 masked categorical 采样，记录观测、当时的 mask、动作、行为 log probability 和 value。环境 RNG 与动作 RNG 分离。

每个座位有独立的决策序列，EndTurn 和等待战斗不截断序列。座位淘汰或获胜后，其最后一个动作获得终局奖励：

```text
reward = 1 - 2 * (placement - 1) / 7
delta_t = reward_t + gamma * value_(t+1) - value_t
advantage_t = delta_t + gamma * lambda * advantage_(t+1)
return_t = advantage_t + value_t
```

其余奖励为 0，终局 value 为 0，GAE 按座位分别计算；gamma 是同一座位每次决策的折扣。默认 gamma=1 保留最终排名目标。GAE helper 支持未结束序列的 bootstrap，但当前采集器只输出完整 episode。

该流程不使用 MCTS/PUCT、假想结束状态、分支续跑、teacher 模仿、EMA actor 或跨轮 replay。Actor advantage 在整轮新样本上统一标准化；critic 的 lambda-return 不做同样处理。每个 epoch 重新打乱当前样本，更新完成后丢弃整轮数据。

### PPO 更新

```text
ratio = exp(new_log_prob - old_log_prob)
policy_loss = -mean(min(ratio * advantage,
                       clamp(ratio, 1-clip_range, 1+clip_range) * advantage))
loss = policy_loss + value_coef * mean((value - return)^2) - entropy_coef * entropy
approx_kl = mean(exp(log_ratio) - 1 - log_ratio)
```

使用 AdamW 和全局梯度范数裁剪。默认 value 输出为 tanh，GAE target 不裁剪。当前只有终局奖励，γ=1 且 bootstrap/value 有界，此时 λ-return 是有界 n-step return 的加权平均，理论上仍在 [-1,1]；采样噪声本身不会破坏这个性质。`--clip-value-target` 仅裁剪 critic 的回归目标，不改 actor advantage，供诊断对照使用。

### 信用分配与 critic 消融

下列实验选项保存在 checkpoint 中，恢复时继承。其中逐决策 λ=0.96、Freeze-and-End 和终局辅助系数 0.1 已组合选为下一轮 baseline；其余作为消融选项保留。新增布尔开关在 CLI 中仍默认关闭。

| 选项 | 含义 |
| --- | --- |
| `--gae-lambda 0.97` | 保持逐决策衰减，只在原值附近调整 λ |
| `--gae-within-turn-lambda 1.0` | 同座位同回合的 trace 系数为 1；跨 Δ 个回合用 `gae_lambda^Δ`，γ 仍按决策步应用 |
| `--freeze-at-end` | 原 Freeze 输出槽改成 Freeze-and-End；只在 End 合法且存在未冻结商店卡牌时开放，保留 must-spend 和 Cancel 逃生规则 |
| `--terminal-value-coef 0.1` | 在原 critic 损失上增加对实际终局奖励的监督；不修改 actor 的 GAE |
| `--critic-distribution` | 将 value 最后一个线性层改为 8 类名次分布，期望奖励供 GAE 使用；λ-return 投影到相邻两个奖励区间并用交叉熵训练 |
| `--critic-health` | 增加预测不早于第 t+3 回合的下一次决策时血量与护甲之和的辅助输出；死亡后目标为 0，游戏提前结束但仍存活的目标不参与损失 |
| `--health-value-coef 0.1` | 血量辅助损失权重，仅在启用对应输出时生效 |

Freeze-and-End 在一次策略决策中调用必要的引擎 Freeze 和 EndTurn，保持引擎效果与动作预算；不增加网络动作数。普通 End 保留引擎结束回合行为。训练、CPU/CUDA 评估、混桌、联赛和开局采集均读取各自 checkpoint 的规则，因此新旧动作语义的模型可以同桌比较。

标量 critic 的终局辅助损失为 `mean((V(s_t) - R_final)^2)`，在同一玩家的每个决策上使用该局实际终局名次奖励作为标签。下一轮 baseline 的 critic 总损失为 `0.5 * MSE(V, lambda_return) + 0.1 * MSE(V, R_final)`，共用原 value 输出、不增加参数；actor advantage 仍按 GAE 计算。当前 γ=1，终局标签不按距离折扣。它提供直接的长期监督，但单局名次噪声较大；组合收益不能直接归因于该损失一项。

分布 critic 的奖励支持为八个名次对应的 `1, 5/7, …, -1`；其 `value_loss` 是交叉熵，不能与标量 critic 的 MSE 直接比较。终局辅助项也随之使用名次交叉熵。未来血量按 60 归一化、限制到 [0,1] 后映射到 [-1,1]，只作为辅助标签，不进入观测或 actor reward。主干与输入不变；标量 value head 增加分布输出、血量输出或两者时，分别新增 903、129、1032 个参数。严格相同参数量的结论应只使用不增加输出头的方案。

默认分布损失监督的是**标量 λ-return 的插值标签**，其期望保持原目标；并非对完整未来回报分布作 Bellman 更新。因此八个输出不能直接解释为经过校准的实际名次概率。实际终局名次交叉熵是另一个监督项，实验中也单独测试了只使用该监督的版本。

`target-kl=0.02` 在某 minibatch 超阈值时，**先停止，再决定不执行该批更新**，并结束剩余 epochs；设为 0 可禁用检查。因此配置 epochs=3 不代表实际使用了三轮完整数据。`clip_fraction` 是概率比超出 PPO 区间的比例，与梯度裁剪不同。

模拟错误或 driver stop 使采集失败；引擎达到配置的游戏回合上限时会判定名次，该名次作为终局奖励，并记为 `turn_limit_games`。战斗截断另记 `truncated_combats`。修改 `--max-turns` 会改变学习任务。

### Checkpoint 与可复现性

每轮结束原子替换 `--out` 指定的 `.npz`，保存权重、AdamW moments/step、shuffle RNG、累计游戏种子位置、超参数、schema/card 元信息和 history。它同时用于推理和轮边界精确恢复。`--save-every N` 额外保留 `model.iterN.npz`，`model.history.json` 提供可读历史。

`resume` 继承保存的全部训练超参数，允许改变累计目标轮数、workers、输出路径和归档频率；另可显式选择设备和切换执行后端。默认覆盖传入的 checkpoint；从归档恢复且想保留原归档时应指定新的 `--out`。不保存中途游戏状态，不支持 v1 权重或 trainer snapshot。

规则或超参数对照使用独立的 `fork` 子命令：保持网络、Adam、RNG、历史和训练计数，仅修改显式指定的选项并写入新路径。支持 `--block-consecutive-freeze true/false`、`--freeze-at-end true/false`、`--lr`、`--games`、`--epochs`、`--entropy-coef`、`--gae-lambda`、`--gae-within-turn-lambda`、`--value-coef`、`--terminal-value-coef` 和 `--health-value-coef`；未指定的项全部继承。`--clear-gae-within-turn-lambda` 恢复逐决策 GAE，与设置回合内 λ 互斥。分叉不改变网络结构或训练种子。

旧 checkpoint 没有策略规则字段时按关闭处理；`fork` 拒绝覆盖已有路径，并在保存前验证参数。`resume` 本身不覆盖保存的规则或超参数。从候选的 1000 轮 checkpoint 调参后训练到 3000 轮，累计预算仍是 3000 轮，不能将续训的 2000 轮当作从头训练成本。

`--games` 只改变分叉后的采样量，历史游戏数不会重置。`--epochs` 只改变后续更新次数上限，仍受 KL 提前停止约束。比较不同 games 或 epochs 配方时必须同时报告累计游戏数、采集与实际用于更新的样本数、耗时；不能仅凭训练轮数判断样本效率。

```bash
target/release/tavernagent_v2 fork \
  --checkpoint runs/tavernagent_v2/model.iter2000.npz \
  --out runs/freeze-test/initial.npz --block-consecutive-freeze true
target/release/tavernagent_v2 resume \
  --checkpoint runs/freeze-test/initial.npz --iterations 10000 --workers 32 \
  --save-every 100 --out runs/freeze-test/model.npz
```

采集和梯度计算在不同阶段复用 Rayon 池。梯度固定按 32 行分块，逐元素归并顺序固定；归并与 AdamW 再按 4096 个参数划分任务。在相同平台和构建下，改变 workers 不改变游戏流、样本顺序和更新结果。

### 诊断指标

历史记录采样/更新耗时、transition 数、回合上限、损失、熵、KL、clip fraction、梯度范数和更新次数。额外区分：

| 指标 | 含义 |
| --- | --- |
| `trained_samples` / `evaluated_samples` | 实际参与更新的样本 / 已计算的样本，后者含被 KL 拒绝的批次 |
| `first_epoch_samples` / `effective_epochs` | 首轮实际覆盖 / 实际数据复用次数 |
| `rollout_seconds` / `prepare_seconds` | 完整游戏采样 / GAE 与样本整理 |
| `gradient_seconds` / `reduction_seconds` / `optimizer_seconds` | 前后向 / 梯度归并 / AdamW 等更新阶段 |
| `cleanup_seconds` / `checkpoint_seconds` / `iteration_seconds` | 缓冲清理 / 保存 / 完整迭代墙钟时间 |
| `critic.all` / `critic.by_turn` | 更新前的预测对 λ-return、最终奖励的 explained variance、MSE、偏差，以及目标越界数；按回合明细每 50 轮保存 |

保存完成后才知道的完整迭代、写文件耗时输出在 stdout JSON，不包含在该 snapshot 自己的 history 中。内存随完整游戏批次的决策总数增长，内存不足时优先降低 `--games`。

八个座位的合计平均名次恒为 4.5，不能用来衡量进步；自博弈 seat-0 名次也仅作诊断，强度使用固定对手评估和 checkpoint 联赛。

可对冻结的 checkpoint 采集独立自博弈样本，只诊断而不更新参数：

```bash
target/release/tavernagent_v2 diagnose --model runs/tavernagent_v2/model.npz \
  --games 128 --workers 16 --seed 70000000 --out runs/tavernagent_v2/critic.json
```

Explained variance 为 `1 - Var(target - prediction) / Var(target)`；目标方差为零时输出 null。它按决策样本统计，不能把同一局的多个决策当成独立游戏构造置信区间。全局指标会混合不同回合，应同时查看按回合结果。

不同 checkpoint 的独立自博弈会产生不同状态分布，λ 的变化也会改变 λ-return 目标；因此跨模型 EV 的变化不等于在相同测试状态上的预测改善。早期终局奖励 EV 较低还可能包含未来随机性，不能单凭该数值认定 critic 出错。强度结论仍由冻结对手评估支持。

## 评估协议

固定 bot 评估使用模型在座位 0 对七个相同 bot 的平均排名，越低越好。早期学习主要观察这一指标，接近饱和后主要观察下文的 checkpoint 联赛 Elo。`scripted` 与 `teacher` 分开记录；JSON 还包含前四率、吃鸡率、平均排名标准误、近似正态 95% 区间及逐局排名。

Teacher 原样复制自 v1 的 deterministic no-composition teacher，保留升本曲线、对子/三连偏好及早期 Dark Gift 策略。Bot 决策保留环境 RNG，所有座位使用同一外部选英雄策略。主比较使用 greedy，`--sample` 作为单独诊断。

`arena` 使用四个候选模型对四个冻结参考模型，均为 greedy，各自读取 checkpoint 中的策略规则。每个环境种子跑两个互补座位布局，并轮换分组位置。`--games` 必须为正偶数，1024 局对应 512 个环境种子；标准误按种子配对后的均值计算，不把同一局的四个候选座位当成独立样本。候选组平均排名低于 4.5 表示相对参考组占优，团队吃鸡率的中性值为 50%。

```bash
target/release/tavernagent_v2 arena \
  --candidate runs/freeze-test/model.npz --reference runs/tavernagent_v2/model.iter2000.npz \
  --games 1024 --workers 16 --seed 20000000 --out runs/freeze-test/arena.json
```

### 完整对局导出与文字回放

`eval --out` 保存汇总 JSON；额外指定 `--replay` 可导出完整对局 JSONL，每行一场，按游戏种子顺序排列。支持 `scripted`、`teacher`，以及 `--opponent selfplay`：八个座位使用同一个 checkpoint，各自维护动作历史和规则。默认 greedy；`--sample` 按策略概率采样，更接近训练时的自博弈行为，但不更新参数。

下面使用快速使用示例训练得到的模型，生成一场自对弈回放：

```bash
cargo build --release -p tavernagent_v2
target/release/tavernagent_v2 eval \
  --model runs/tavernagent_v2/model.npz --opponent selfplay --sample \
  --games 1 --workers 2 --seed 120000000 \
  --out runs/replay/selfplay-summary.json --replay runs/replay/selfplay.jsonl

# 固定 bot 的完整对局也可以导出
target/release/tavernagent_v2 eval \
  --model runs/tavernagent_v2/model.npz --opponent teacher \
  --games 2 --workers 2 --seed 120000001 \
  --replay runs/replay/teacher.jsonl
```

在仓库根目录执行 `python3 -m http.server` 后，用浏览器访问该服务的 `/tools/ppo_replay/`。页面自动显示“服务器文件”，从服务根目录逐层进入文件夹，点击 JSONL 即可直接读取，无需浏览器文件选择或上传。也可以填写服务器路径（例如 `/runs/replay/selfplay.jsonl`）直接打开；“刷新”用于查看新生成的文件。目录浏览兼容 Python `http.server` 的目录列表，不递归扫描整个仓库。

链接可以附带 `?replay=/runs/replay/selfplay.jsonl` 自动加载指定文件，路径指向使用者按上文命令生成的产物。若目录存在首页而不显示目录列表，仍可直接填写 JSONL 路径。只读取当前 HTTP 服务提供的文件，不访问服务器文件系统的其他位置。

也可以直接用浏览器打开 [文字回放页面](../tools/ppo_replay/index.html)，点击“选择本机文件”读取 JSONL；这种方式不上传内容。两种方式均无需构建或第三方前端依赖。可以切换对局、玩家、回合，展开决策前后的金币、手牌、商店和阵容，查看动作概率与 value、每回合对手和伤害，以及最终名次。点击“最后一战”查看最后一个战斗回合的全部存活玩家；只有该回合恰好两人存活时才标为二人决赛。最终排名表保留每位玩家最后一次战斗前的阵容。

导出覆盖八个座位，固定 bot 对局也会在零号玩家淘汰后继续到整局结束。汇总指标仍针对零号玩家，固定 bot 的诊断和异常计数保留原来的评估截止口径；JSONL 中的名次与异常计数覆盖整局。自对弈汇总同样只统计零号玩家，不能把它作为独立的绝对强度分数。

格式标识为 `schema="tavernagent_v2.replay"`、`version=1`；每行包含模型轮数及训练种子、后端、策略规则、游戏规则、八席 `placements` 和 `events`。64 位游戏种子与模型种子以字符串保存，避免浏览器整数精度丢失。事件如下：

| type | 内容 |
| --- | --- |
| `turn_start` | 八个玩家的回合开始状态，包含已选英雄 |
| `action` | 玩家、控制策略、引擎动作、动作前后状态；模型动作另有紧凑动作索引、选择概率、value 和 Freeze-and-End 标记 |
| `combat_start` | 全部回合结束效果结算后、战斗随机数消耗前的八席状态；用于回合结束阵容 |
| `combat_end` | 实际配对、胜负、伤害、截断标记及结算后状态 |
| `game_end` | 八席最终状态与名次 |

若动作触发整轮战斗，其 `after.turn` 可能已进入下一回合；页面会标注，不将此快照当作上一回合战前阵容。记录通过引擎暂停/恢复接口捕获战斗边界，不增加随机采样，不记录选英雄的独立随机决策或逐次战斗攻击动画。到达回合上限、战斗截断会显式显示。

CPU 记录路径已验证开启记录前后的名次、诊断和 RNG 一致，以及不同 workers / batch 下完整回放一致。导出会增加时间和文件体积，建议先用 1–2 局观察；内存中最多保留四场完整回放。浏览器单文件限制为 256 MiB，较大评估应减少单次导出局数。回放文件存在时拒绝覆盖；成功后发布最终文件，失败时删除本次 `.partial`。没有传入 `--replay` 时不保存完整状态。

### Checkpoint 联赛与 Elo

打固定 bot 的平均排名接近 1.2 后，继续保留这一指标作行为回归检查，训练阶段的相对强度主要看 **每 500 轮 checkpoint 的共享联赛**。`league` 复用 v1 的评估口径：每桌八个不同 checkpoint，随机分配座位，记录八席完整名次；[league_elo.py](../tools/league_elo.py) 用 Plackett–Luce 拟合强度，按 `400 × log10(strength)` 转成 Elo。它与 `arena` 的两模型 4v4 评估分别使用。

联赛使用 CPU `infer_f32` 和 greedy 动作，每席读取自己的 checkpoint 策略规则，因此可以同时比较不同宽深、训练种子及 Freeze 规则。所有模型的引擎规则必须一致。CPU/GPU 训练出的 checkpoint 统一使用同一评估后端；不使用 MCTS。模型池至少需要八个 checkpoint，同桌不重复模型身份。

固定一个已冻结的 checkpoint 为 **Elo 1000**，将所有训练曲线放在同一个连通对手池中；bootstrap 的每次重采样也固定同一锚点。Elo 是池内相对分数，加入新模型或新对局后旧模型分数可能变化。不能直接比较不同池、不同锚点的绝对 Elo。误差来自以完整游戏为单位的 bootstrap，不能代替多个训练种子的波动；仍应分别检查各训练种子的曲线。

```bash
# 使用快速使用示例续训至 5000 轮后生成的 checkpoint；输出文件必须尚不存在
models=()
for step in 500 1000 1500 2000 2500 3000 3500 4000; do
  models+=(--model "run_s${step}=runs/tavernagent_v2/model.iter${step}.npz")
done
target/release/tavernagent_v2 league "${models[@]}" \
  --rounds 256 --workers 16 --seed 60000000 --out runs/league/games.jsonl
python3 tools/league_elo.py runs/league/games.jsonl --anchor run_s500 \
  --bootstrap 200 --json runs/league/ratings.json --out runs/league/elo.png
```

[ppo_league.py](../tools/ppo_league.py) 可持续发现多个目录的 `model.iterN.npz`，以及保存了非零整 500 轮状态的 `initial.npz`。默认每个 checkpoint 至少 256 局，每批 64 局；每桌四席优先补足出场较少的模型，另外四席随机抽取其余对手，使新旧 checkpoint 有交叉对局。座位随机化，对局数为下限，成熟 checkpoint 可能继续出场。

`--reference LABEL=CHECKPOINT` 可额外加入冻结基线，不受候选训练轮数上限限制。例如候选最多训练 3000 轮时，仍可加入 5000 轮基线；它不参与训练轨迹完成条件。其标签须与 `--run` 不同。

多轨迹监控示例如下；先用 `train --out` 将各组训练产物保存到对应目录，再将实际使用的目录传给 `--run`。这些目录及锚点模型需要由使用者训练生成。

```bash
python3 tools/ppo_league.py --binary target/release/tavernagent_v2 \
  --run control=runs/control --run no_repeat=runs/no-repeat --run wider=runs/wider \
  --out runs/shared-league --anchor control_s2000 --interval 500 \
  --games-per-model 256 --target-iteration 10000 --workers 16 --watch
```

监控器只读取归档 checkpoint，不修改训练参数。它保存模型哈希、冻结桌次、独立环境种子、完整名次及 `ratings.json` / `ratings-meta.json` / `status.json`。不足八个模型时等待；新 checkpoint 自动加入并补足对局，全部指定训练轨迹到目标轮数且满足出场下限后退出。相同命令可以恢复中断任务，已完成批次只计入一次。Rust 命令以 `.partial` 暂存，完整批次原子发布；重试使用同一桌次和种子。不合法排名、重复记录或不连通的评分图会报错。达到回合上限或出现战斗截断的对局保留在原始批次及 `excluded-games.json` 中，不计入 Elo 和有效出场数；调度器继续补足有效对局，报告同时列出排除数量。

`--exclude-model RUN_sITERATION` 可重复指定精确的 checkpoint 标签：不再注册或调度该条目，拟合时剔除包含它的**整场对局**，并在 `excluded-games.json` 记录 `excluded_model` 原因；权重和原始批次保留。排除清单写入 manifest 和评分元数据，不能排除固定锚点。它属于评估协议变更，已有输出目录不能直接换参数恢复；需先归档旧结果，再建立新协议的输出目录。事后排除的原始成绩应单独报告，过滤后的图不代表训练全程稳定。

调度器需要 Linux、Python 3.11+，Elo 拟合需要 NumPy；绘图额外需要 Matplotlib，`league_elo.py --no-plot` 可以仅输出评分。Rust 联赛执行文件本身不需要这些依赖。评估使用独立资源预算，训练与联赛的吞吐应分别统计。

### 定期通知

[ppo_notify.py](../tools/ppo_notify.py) 向已配置的飞书会话发送纯图片卡片，固定依次放置 **scripted bot 平均排名、teacher bot 平均排名、arena Elo** 三张图，不包含卡片标题或文字汇报。默认每 30 分钟发送一次，每分钟检查状态；失败、停止、完成或故障恢复也触发同样的三图通知。读取失败连续三次、运行状态超过 15 分钟未更新时触发通知。全部指定任务完成且最后一张卡片发送成功后退出。

图中按训练种子绘制 CPU 两组与 GPU 模型的历史曲线。Bot 图同时显示完整历史和 500 轮后的排名局部放大，误差条为游戏采样的近似 95% 区间；局部图只显示排名不超过 2.5 的区域，异常高排名仍完整保留在全局图中。Elo 图使用已完成的评分文件，显示对局数及整局 bootstrap 的 95% 区间，不重新拟合 Elo。三张图必须全部上传成功才发送卡片；失败时保留待发消息和 UUID 重试，不发送文字替代或不完整卡片。

通知是可选功能，运行前需由使用者创建 JSON 配置及凭据文件，仓库不包含任何已部署的通知配置。运行位置、SSH 参数、凭据文件路径按自己的部署填写，不提交版本控制。配置包含 `out`、`credentials_env`、`interval_seconds`、`poll_seconds` 和 `sources`；`sources` 的 `cpu` / `gpu` / `league` 各指定 `ssh` 参数数组及 `files` 映射。训练来源需要 `status`，联赛还需要 `ratings` 和 `ratings_meta`。训练来源另配置 `eval_runs`，每项指定 `name`、`training_seed`、`directories` 和可选 `evaluation_seed`（默认 10000000）；多个目录中的同一 checkpoint 评估去重，保留游戏数较多的结果，过滤 sampled 或其他评估种子的结果。凭据文件使用 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_HOME_CHANNEL` 和可选 `FEISHU_DOMAIN`；凭据不写入通知或日志。下面假定使用者将自行创建的配置保存为 `runs/notifications/config.json`。

## 吞吐与并发

`workers` 控制采样和更新阶段共用的 Rayon 线程池。默认值 16 是起点，实际并发应通过 [吞吐工具](../tools/ppo_throughput.py) 在目标运行环境测量。单任务延迟与多任务总吞吐应分别比较，并为评估预留资源；不要直接把单任务最优 workers 乘以任务数。

测试时固定模型、games、batch、训练超参数和随机种子，排除预热轮次。记录决策数/秒、实际训练样本数/秒、每轮耗时和峰值内存；相同轮数的速度差可能来自 KL 提前停止造成的更新次数差异，或策略退化导致对局变长。模型、批次或训练阶段改变后应重新测量。

### 已保留的性能优化

原实现按整张矩阵分配梯度归并和 AdamW 任务；输入投影含 940,032 个参数，约占模型 40.6%，造成调度不均衡。现按 4096 个参数分块，逐元素求和顺序和 Adam 算式保持不变。梯度计算固定按 32 行分块，使 workers 改变时仍保持一致的归并顺序。

配对验证中，最终 142 个网络/Adam/schema 数组逐字节一致，优化器步数、RNG 和训练计数相同；耗时历史不参与比较。后续可评估训练梯度缓冲复用、减少梯度重复清零，以及分块大小的内存/GEMM 折衷。当前分段计时不能单独证明缓存或内存带宽瓶颈。

CPU `infer_f32` 使用线程局部工作区，复用输入、实体编码、主干、动作头和值头的临时缓冲；实体编码和对象动作头有独立的无反向缓存推理路径。工作区不保存权重，各次调用重新写入输入并读取当前参数，可在不同结构、宽度和 checkpoint 之间复用。保留全部动作 logits，不跳过非法动作或改变 mask。矩阵乘法支持写入已有缓冲，训练时 LayerNorm 反向的行缓冲也在行之间复用。

CPU 训练前向一次计算 GELU 激活与导数，共用一次 `tanh`，将原先保存激活前数值的缓冲改为保存导数；反向直接相乘，不再重复求 `tanh`。SiLU 同样复用 sigmoid，ReLU 保持原定义。参数布局、PPO 配方、梯度分片和归并顺序不变；这是 CPU 执行优化，CUDA 训练内核未修改。测试对照原公式的激活/导数，以及原分配式推理路径，覆盖工作区扩缩容、跨模型、参数变化、空实体和错误输入后的再次调用，并保留全网有限差分与 checkpoint 恢复检查。

该优化分别从 B-5000、C-3500 的同一 checkpoint 对照续训 5 轮，64 局/轮、16 workers，包含启动首轮。C 的旧实现已包含动作头投影复用。结果如下；这是短程测速，不是不同结构的同预算强度比较。

| 模型 | 优化前秒/轮 | 优化后秒/轮 | 吞吐提升 | 前后向计算秒/轮（前 → 后） |
| --- | ---: | ---: | ---: | ---: |
| B | 6.180 | 5.897 | 4.8% | 2.879 → 2.576 |
| C | 8.061 | 7.459 | 8.1% | 3.965 → 3.448 |

两组各自的决策数一致，续训后 B 的 225 个、C 的 285 个网络/Adam/schema 数组逐字节一致，训练选项、优化器步数、RNG 和训练计数一致；耗时历史不参与一致性比较。62 项测试及 Clippy 检查通过。收益主要来自训练前后向，短测中的采样耗时变化较小；工作区复用不等于消除了矩阵乘法内部的全部临时分配。

正式 B 两种子分别从 5581、5606 轮，C 从 4004、3953 轮的完整 checkpoint 切换，累计目标仍为 10000 轮。切换后 64 workers 的初步窗口中，B 各 21 轮均值为 3.175 / 3.264 秒，C 各 16 / 17 轮均值为 4.103 / 4.002 秒；不同窗口的决策量有变化，不能将前后耗时差全部归因于实现优化。固定 bot/arena 评估继续使用原评估二进制，checkpoint 入池与通知规则不变。

### 连续 Freeze 规则对照长训

后续对照比较原配方与屏蔽连续 Freeze 的效果。两组各使用 A 的五个 2000 轮 checkpoint（种子 400000000 至 800000000）。原计划累计 10000 轮，后按实验预算调整，将 CPU 的分析截止点改为 **6000 轮**并停止；超过截止点的产物保留但不用于这一轮结果。同期更大网络的 GPU 实验上限改为 3000 轮，实际在 2815 轮触发内存保护后结束，与 CPU 数据统一归档。这是执行中的预算调整和保护停止，不是预先声明的 6000/2815 轮终点。

| 组 | 连续 Freeze 规则 | 其余设置 |
| --- | --- | --- |
| `control` | 关闭 | A 原配方，原 Adam/RNG/训练计数继续 |
| `no_repeat_freeze` | 开启 | 与对应 control 从相同 checkpoint 分叉 |

网络、奖励、lr=1e-4、λ=0.95、entropy=0.03、epochs=1、games=64、batch=1024 保持一致。使用 `fork` 仅改变规则开关，两组从相同权重、Adam 状态、RNG 和训练计数继续。关闭规则的新实现与增加规则前的实现，经三轮续训验证，142 个数组及训练状态完全相同；改变 workers 的配对验证也保持一致。历史诊断日志的 JSON 浮点重编码只允许末位误差，训练状态和数组仍要求精确一致。

连续重复屏蔽在 6000 轮没有体现稳定收益，保留默认关闭。固定 bot 接近饱和，因此后续以冻结模型间对战为主要比较口径，不据此推断对人类或 v1 的强度。

同期 384×8 的单种子 FP32 CUDA 训练存在明显的中途回退：teacher 平均排名在 1900/2000/2100 轮分别为 1.8320/6.7637/1.2842（各 1024 局）。对 2000 轮权重另用 CPU FP32 推理复核 128 局，平均排名为 6.8125，确认弱表现并非仅出现在 CUDA 评估。1901～2000 轮全部触发 KL 提前停止，平均有效训练 epoch 仅为 0.0523，随后恢复。该异常保留在完整曲线中；原因尚未定位，不能将单次回退归因于模型宽度或某个训练参数，也不能用恢复后的单个 checkpoint 代表训练稳定性。

2815 轮再次退化，64 局自博弈中有 25 局达到 100 回合上限，采样量增至 316002 条决策，随后触发进程内存保护。原训练参数保持不变，最终权重保存为 2815 轮；不存在 3000 轮结果。终点改用 CPU FP32 greedy 评估，每类 bot 各 1024 局：scripted 平均排名 7.8398，teacher 为 7.8027；对同一宽模型的 500 轮参考做 1024 局配对混桌，平均排名为 6.4053。三项评估均没有回合上限或战斗截断。保留 2500 轮的恢复点与 2815 轮的失败终点，不能只报告峰值。

#### 实验设计与完整初筛

基线为上述五个 control 的 5000 轮 checkpoint。常量配方候选从头训练，主干保持 256×6，每轮 64 局，最多 3000 轮；先用两个配对训练种子筛选，再用五个种子复验候选，分别报告参数不变的改动与增加少量辅助输出的改动。另设公共前缀分叉对照，前缀训练计入累计步数和游戏数。

两个原配方对照训练到 500、1000 轮时，分别与第一轮同种子、同轮数 checkpoint 的 141 个数值数组、优化器步数、训练计数和 RNG 完全一致。新增诊断没有改变这两个对照的训练结果。另将原配方五个 3000 轮模型各与同种子 5000 轮基线混桌 512 局，作为同预算参照：平均排名 4.6843，按训练种子及共享游戏种子两维重采样的 95% 区间为 [4.6167, 4.7459]，五个种子都落后于 5000 轮基线。这是验证集结果；新方案的主要目标仍是跨过 4.5，而不只是超过原配方的 3000 轮表现。

主要指标为对固定 baseline-5000 的配对 4v4 混桌名次，4.5 为持平；辅以共享联赛 Elo、固定 bot 排名、首次升本回合分布、决策量和 critic 诊断。筛选使用 80000000 起的游戏种子，最终保留集使用 90000000 起的新种子。CPU 按相同训练种子匹配基线；CUDA 复验的最终比较覆盖全部五个基线，避免把参考对手差异当作配方收益。

最后一个组合还用 FP32 CUDA 的两个独立种子 900000000、1000000000 从头训练到 3000 轮，主干仍为 256×6，参数量和每轮游戏数与基线相同。名次分布 critic 的 CUDA 复验使用种子 400000000、500000000，终点在读取保留集前按预算固定为 2500 轮。相同初始化种子不保证 CPU/CUDA 浮点训练轨迹完全一致；CUDA 两种子结果不能替代 CPU 五种子复验。

最终清单在读取保留集前冻结：上述六类 CPU 候选各五个 3000 轮模型，原配方五个 3000 轮模型，以及两种 CUDA 配方各两个训练种子对五个基线的交叉比较，共 55 项，每项 4096 局。整对互补座位对局中只要有一局出现回合上限或战斗截断，就从配对统计中排除，同时保留原始结果与排除数量。不按保留集回选中间 checkpoint，也不继续调参。

主要结论要求平均混桌名次低于 4.5、区间支持提升且跨种子方向一致。报告普通 95% 区间和覆盖全部八类候选比较的近似 Bonferroni 校正区间；CPU 按训练种子及共享游戏种子重采样，CUDA 交叉比较再重采样参考种子。另报后加的三个 CPU 种子作为次要一致性检查：新游戏种子不能消除前两个训练种子参与筛选的影响，少量训练种子也限制 bootstrap 区间的可靠性。

每 500 轮保留的完整验证曲线用于检查进步与回退，不据此回选最终 checkpoint。最终 55 项留出评测均完成，共 225280 局；其中 5 个评测游戏对出现战斗截断，共 32 次截断，没有回合上限终局。统计使用各比较组共有的有效游戏对，原始结果和排除记录均保留。

最终混桌后，已对 39 个不同终点模型各采集 128 局作 critic 诊断，与五个 baseline-5000 的诊断对照。不同策略的状态分布和 λ-return 目标并不相同，不能仅凭更高的 explained variance 判定策略更强；早期终局奖励预测困难也可能来自后续随机性，不能直接归因于 critic 实现错误。

开始前，对五个 baseline-5000 各采集 128 局独立自博弈作 critic 诊断：对 λ-return 的全局 explained variance 为 0.918～0.929，对实际终局奖励为 0.421～0.473；第二回合对终局奖励仅为 0.027～0.081。约 146 万条决策的 λ-return 越界数为 0。该结果支持进一步检查早期信用分配，但不能单独证明某个 critic 结构会改善策略。

五个 baseline-5000 对 teacher 的 5120 局 greedy 评估中，第二回合首次升本为 **0 局**，首次升本在第五或第六回合占 **84.24%**；6000 轮时仍为第二回合 0 局，第五或第六回合占 76.97%。这些是行为诊断，不把固定升本回合写成训练奖励，也不能仅凭该比例判定模型强弱。

另用 81000000 起的 512 个配对游戏种子，对每个冻结基线进行一次仅评估的干预：第二回合若升本合法且仍为一星，强制升本一次，之后继续原策略。每个模型有 508/512 局满足条件。五模型平均排名从 1.1941 变为 1.2371，差值 +0.0430；按训练种子及共享游戏种子两维重采样的 95% 区间为 [-0.0074, 0.0941]，未显示收益。该干预没有训练与早升本配套的后续策略，不能据此判断早升本策略本身的上限。

第一回合最常见完整顺序为“买随从 → 打出 → 结束”，占 42.09%；第二回合为“买随从 → 打出 → Activate → Choose → 结束”，占 19.82%，其次“刷新 → 买随从 → 打出 → 结束”占 8.30%。

第一回合买过随从/法术的游戏占 69.90%/25.23%，第二回合为 76.33%/35.16%。高频购买包括可疑的监狱守卫、夺金健将和拔线机；购买频次不等于相同备选下的偏好胜率。

第一回合结束时 83.50% 有一个随从、4.41% 有两个、12.09% 空场；第二回合 74.92% 有两个、19.26% 有一个、4.61% 有三个、1.21% 空场。两回合花光金币的比例为 94.65%/95.31%，所有结束状态少于 3 金币，均显式 EndTurn，没有动作上限强制结束。

### 不升本与冻结循环

五个模型第二回合 greedy 升本次数均为 0，约 95.16% 的第二回合初始状态允许 Upgrade；初始决策点的平均升本概率仅约 0.034%。采样对照也仅有 5/5120 = 0.098% 的游戏第二回合升本。这说明低升本倾向在策略分布中已存在，不能解释为普遍被 mask 禁止，也不能据此推断后续回合都不升本或该开局最优。

第一/二回合分别有 **9.88%/15.23%** 的游戏连续按五次 Freeze，触及既有冻结次数上限，五个模型都有该现象。例如训练种子 400000000、游戏种子 10000000 的苔丝，第二回合英雄技能后连续五次冻结/解冻，接着刷新、买法术联盟旗帜再使用，增加了冗余决策。

概率采样时，至少按一次 Freeze 的比例更高，为 64.18%/72.05%，但连续五次的比例降为 2.09%/1.93%。greedy 会重复某些局部状态的 Freeze 偏好。这促成了上文的连续 Freeze 规则对照；开局策略仍需单独研究。较好的固定 bot 排名不意味着动作效率已理想；这些轨迹来自规则关闭的原始 A 模型。

## 后期 λ 扫描：5000→10000 轮

此批正在运行的实验使用新增 `costs_health` 前的 3236 浮点观测与对应二进制，未部署本次输入变更。

使用 C 的 **seed1100000000、5000 轮完整 checkpoint**，分别以 **GAE λ=0.96（对照）、0.97、0.98、0.99** 分叉，四条分支同时训练至 10000 轮。保留相同网络、Adam、RNG、累计游戏数与训练计数。统一显式启用余弦学习率：5000 轮 1e-4、10000 轮 2e-5，之后保持 2e-5。固定 terminal-value-coef=0.1、value-coef=0.5、entropy-coef=0.03、Freeze-and-End、games=64、epochs=1、batch=1024、C/320×6/embedding32。唯一组间变量为 λ。

新建共同 arena，加入两个历史种子各自的 1000～5000 轮、每 1000 轮一个 checkpoint（共 10 个）作为参照，锚定 seed1100000000 的 1000 轮模型为 Elo 1000。本轮四组每 500 轮保存完整 checkpoint 并加入同池（5500～10000，共 40 个）。历史参照不作为额外训练种子，也不加入之前的后期学习率实验模型。每个新模型初筛至少 512 次参赛，scripted/teacher 各 256 局作为次要指标；每个 checkpoint 完成评估后通过现有通知通道发送三张结果图。

记录实际学习率、KL 提前停止率、更新覆盖率、梯度范数、value/终局损失及吞吐。最终选优前建议为候选终点补齐相同评估预算，避免按单个 checkpoint 峰值选优。总预算新增 20000 轮、1280000 个完整游戏。此次按用户选择只做一个训练种子；C 既往双种子表现相近不意味着 λ 效果也必然跨种子一致，结果用于初筛，不估计训练种子间的不确定性。

### 工具用法

[吞吐工具](../tools/ppo_throughput.py) 的 `--cases` 为 **workers × 任务数**。它自动发现可用物理核和 NUMA 拓扑，默认训练参数使用历史 CLI 配方；依赖 Linux、Python 标准库、`numactl`、`lscpu` 和 `/usr/bin/time`。每次使用新的输出目录，保存命令、资源指标和 checkpoint；`--repeats` 交替顺序重复扫描。

```bash
cargo build --release -p tavernagent_v2
python3 tools/ppo_throughput.py --binary target/release/tavernagent_v2 \
  --out runs/ppo-throughput --cases 2x1 4x1 \
  --games 64 --batch 1024 --iterations 20 --warmup 2 --repeats 2
```

选择的 workers 与任务数必须符合运行环境的可用物理核和 NUMA 节点容量。可用 `RUSTFLAGS="-C target-cpu=native"` 构建以测量目标 CPU 的性能；这种二进制只应在兼容 CPU 上运行。

[开局采集示例](../crates/tavernagent_v2/examples/opening_trace.rs) 记录模型前两回合的轨迹；加入 `--sample` 改为概率采样。每步包含动作类型概率、所选卡牌，以及前后金币、手牌、战场和商店。它读取 checkpoint 中保存的策略规则。

```bash
cargo build --release -p tavernagent_v2 --example opening_trace
target/release/examples/opening_trace --model runs/tavernagent_v2/model.npz \
  --games 1024 --workers 16 --seed 10000000 --out runs/opening/trace.json
```

### 产物与复现边界

`runs/` 为 Git 忽略的输出目录。Checkpoint、训练日志、逐局评估和开局轨迹由使用者保存，不随源码分发。本文表格记录已完成实验的汇总结论，示例路径用于新建任务，不指向随仓库发布的模型。

复现实验应同时保存源码版本、构建选项、完整命令、训练与评估种子，以及 checkpoint 中的超参数和策略规则。上文已列出已完成实验的配置、预算和评估协议；历史实验使用提交前的开发快照，当前提交并非那些构建的逐字节副本。
